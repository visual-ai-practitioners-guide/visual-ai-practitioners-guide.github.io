Embed images

An embedding turns each image into a vector of a few hundred to a few thousand numbers. Images that look alike, or that show similar content, get similar vectors. Embeddings feed regressions, clustering, similarity search, and most of the methods further down this page.

Global embedding: one vector per image

The whole image becomes one list of numbers. Use the numbers as regressors, to cluster images, or to find the most similar images.

Patch embeddings: one vector per patch

The image is cut into small squares, called patches, and each patch gets its own vector. Score the patches and you get a map of where something is in the image.

How the two connect: most image models today are vision transformers. A vision transformer cuts the image into squares 14 or 16 pixels wide, called patches. It turns each patch into a vector, and it adds one extra vector that summarizes the whole image, often called the CLS token. After the model has processed the image, the summary vector (or the average of the patch vectors) is the global embedding. The vector for each patch is that patch's embedding.

Model sizes in the tables are counts of parameters, the numbers inside the model (M for million, B for billion). Larger models need a GPU with more memory. Most open models are hosted on Hugging Face (HF), and each model's page there is called its model card.

Compare, group, and search images

Two images are alike when their global embeddings point in the same direction. Cosine similarity measures that, on a scale from -1 to 1, where 1 means the same direction. The code below uses it three ways.

  1. Compare. Score how alike two images are, or how typical each image is of its category: its cosine similarity to the average embedding of that category. A low score marks an unusual image.
Compare images python · numpy 
import numpy as np

# X: DINOv3 global embeddings, one row per image (n x 768), from embed() in Predict outcomes
# category: a NumPy array with each image's category, such as its product type
Z = X / np.linalg.norm(X, axis=1, keepdims=True)   # unit length, so a dot product is a cosine
S = Z @ Z.T                                         # n x n cosine similarities, from -1 to 1
nearest = np.argsort(-S[0])[1:6]                    # the 5 images most like image 0

# Typicality: cosine similarity between each image and the mean embedding of its category
typicality = np.zeros(len(Z))
for c in np.unique(category):
    m = category == c
    proto = Z[m].mean(axis=0)
    typicality[m] = Z[m] @ (proto / np.linalg.norm(proto))
  1. Group. Let a clustering method find groups of similar images. HDBSCAN (in scikit-learn) chooses the number of groups itself and marks images that fit no group as outliers, which are the unique ones. It works poorly in many dimensions, so first reduce the embeddings to about 50 with PCA. For millions of images where you want a set number of groups, e-means (Bessa et al. 2026, in the Faiss library) is a fast version of k-means.

Search images by text python · transformers 
import torch
from PIL import Image
from transformers import AutoModel, AutoProcessor

# image_paths: a list of paths to the image files
# Text search. DINOv3 has no text side, so embed the images again with SigLIP 2.
ckpt = "google/siglip2-so400m-patch16-384"   # tested with "google/siglip2-base-patch16-224", the small one
model = AutoModel.from_pretrained(ckpt).eval()
processor = AutoProcessor.from_pretrained(ckpt)

@torch.inference_mode()
def siglip_images(paths, bs=32):
    out = []
    for i in range(0, len(paths), bs):
        imgs = [Image.open(p).convert("RGB") for p in paths[i:i + bs]]
        e = model.get_image_features(**processor(images=imgs, return_tensors="pt")).pooler_output
        out.append(torch.nn.functional.normalize(e, dim=-1))
    return torch.cat(out)

img_emb = siglip_images(image_paths)                # n x d, unit length
with torch.inference_mode():
    t = processor(text=["a red sports car"], padding="max_length", max_length=64, return_tensors="pt")
    txt_emb = torch.nn.functional.normalize(model.get_text_features(**t).pooler_output, dim=-1)
scores = (img_emb @ txt_emb.T).squeeze(1)           # cosine of each image with the phrase
top10 = [image_paths[i] for i in scores.argsort(descending=True)[:10]]

Use embeddings in a regression

An embedding has hundreds or thousands of columns, often more than you have images, so ordinary least squares breaks down. Use a high-dimensional regression that shrinks or selects coefficients. Common choices are ridge, lasso, and elastic net, with the amount of shrinkage chosen by cross-validation (try each amount on held-out images and keep the best). Bayesian versions such as spike-and-slab or horseshoe priors do the same job and give a posterior distribution for every coefficient, allowing for uncertainty quantification. Use generalized linear model versions to accommodate various outcome types (e.g., binary, count, skewed positive).

Avoid reducing the embedding to a handful of principal components (PCA) by default. PCA keeps the directions where images vary most, and those need not be the directions that matter for your outcome. A handful of linear components can also drop information that the model stored in other directions or nonlinearly.

Often the image is a control and the question is about something else: the effect of price, a promotion, or a person's face in the ad. The image is then a confounder: it is related to both the cause you study and the outcome. DoubleMLDeep (Klaassen et al. 2024) adjusts for such a confounder with double machine learning, the method in the code below, using image and text controls. For an introduction to double machine learning, including an example that controls for text embeddings, see Ahrens et al. (forthcoming, Journal of Economic Literature). The primary concern here for identification is whether overlap is satisfied, so be sure to check for that (e.g., visually with propensity score distribution plots).

Heatmaps from patch embeddings

A heatmap gives each patch of the image a score and colors it. What the score means depends on what you compare each patch with. There are three common choices.

  1. Compare each patch with a reference image, such as your logo (DINOv3). Patches that look like the logo light up.
  2. Compare each patch with a phrase, such as "a bottle" (TIPSv2, or dino.txt for DINOv3). Patches that match the phrase light up. A single map's numbers have no fixed scale. Read a map by comparing it with the maps for other phrases.
  3. Score each patch by its contribution to an outcome (DINOv3). Fit a regression of the outcome on the average of each image's patch embeddings, then apply the fitted coefficients to each patch. The patch scores average to the image's prediction minus the regression's constant (intercept). The map therefore shows how much each patch contributes. For maps of other models, see Explain the predictions.
TIPSv2: map a phrase onto the image python · transformers 
import torch, torch.nn.functional as F
import matplotlib.pyplot as plt
from transformers import AutoModel, AutoProcessor
from transformers.image_utils import load_image

ckpt = "google/tipsv2-b14"   # loads natively as Tipsv2Model; tokenizer needs `pip install sentencepiece protobuf`
model = AutoModel.from_pretrained(ckpt).eval()
processor = AutoProcessor.from_pretrained(ckpt)

image = load_image("ad.jpg")
phrases = ["a bottle", "a person", "a logo", "the background"]   # compare maps across phrases
inputs = processor(text=phrases, images=image, padding="max_length", max_length=64,
                   return_tensors="pt")              # resizes to 448 px, pixels in 0..1, no normalization
with torch.inference_mode():
    img_out = model.get_image_features(pixel_values=inputs.pixel_values)
    txt_out = model.get_text_features(input_ids=inputs.input_ids, attention_mask=inputs.attention_mask)

R, p = model.config.vision_config.num_register_tokens, model.config.vision_config.patch_size   # 1, 14
H = W = inputs.pixel_values.shape[-1] // p                                  # 448 / 14 = 32
patches = F.normalize(img_out.last_hidden_state[0, 1 + R:], dim=-1)        # (1024, 768): skip CLS + register
text = F.normalize(txt_out.pooler_output, dim=-1)                          # (4, 768), one row per phrase
maps = (patches @ text.T).T.reshape(len(phrases), H, W)                    # cosine of every patch with every phrase

# Upsample each map to the image size and overlay it, one panel per phrase, on one color scale.
up = F.interpolate(maps[None], size=image.size[::-1], mode="bilinear")[0]
fig, axes = plt.subplots(1, len(phrases), figsize=(4 * len(phrases), 4))
for ax, phrase, m in zip(axes, phrases, up):
    ax.imshow(image); ax.imshow(m, cmap="jet", alpha=0.5, vmin=up.min(), vmax=up.max())
    ax.set_title(phrase); ax.axis("off")
fig.savefig("tipsv2_maps.png", bbox_inches="tight")

A vision-language model (VLM) reads an image and answers a question about it in text. Give it the question you would give a research assistant, such as "Does this ad show a person using the product?", and you get a label for every image with no training. Use it for concepts a person can define and check. It cannot predict market outcomes it has never seen.

A labeling workflow

The workflow below follows the split-sample framework of Egami, Fong, Grimmer, Roberts, and Stewart (2022, Science Advances). Their paper is about text, and the same logic carries over to images: develop the measure on one part of the data and use it, unchanged, on another.

  1. Split your images at random into a development set and a held-out set. Set the held-out set aside.
  2. On the development set, write a codebook: the question, the allowed answers, and two or three edge cases. The codebook is the prompt you give the model. Revise it as often as you like at this stage.
  3. Freeze the prompt and the model version. Run the model on the held-out images and set it to always give its single most likely answer (greedy decoding), so a rerun gives the same labels. Record the exact model ID and the date. For a closed API, also store every raw response, because a rerun can still differ.
  4. Hand-code a random sample of about 400 held-out images and report how often people and the model agree. Also report inter-rater reliability measures such as Krippendorff's alpha.
  5. If the labels enter a regression, correct for their errors with the methods below.

The embeddings regression is the recipe from Embed images, with one addition called cross-fitting. Split the images into five parts (folds). Fit the regression on four parts and predict the fifth. Fine-tune a model on your own data

Fine-tuning means training an existing model further on your own data. Full fine-tuning updates billions of numbers inside the model, which takes more computing power and data than most research projects have. Parameter-efficient fine-tuning (PEFT) leaves the original model as it is and learns a small set of extra adjustments on top, called an adapter. The adapter fits on one GPU and is saved as a small file next to the model.

The most common PEFT method is LoRA (low-rank adaptation), and plain LoRA applied to every layer is a good default. On small and medium datasets it matches full fine-tuning, provided the learning rate (the step size of each training update) is about 10 times the rate used for full fine-tuning (LoRA Without Regret). The variants in the table change how the adapter is set up or stored, and you can try them with one setting each.

MethodWhat it doesSetting in the Hugging Face peft library
LoRAAdds a small adapter to each layer of the model.LoraConfig
QLoRALoRA on a compressed copy of the model, so a larger model fits on one GPU, at a small cost in accuracy. Unsloth advises against it for Qwen3.5 and Qwen3.6 but supports it for Qwen3.8.bitsandbytes 4-bit + LoraConfig
DoRASplits each adapter's update into a size and a direction, which sometimes trains closer to full fine-tuning but runs slower.use_dora=True

The easiest start on one GPU is a ready-made notebook from Unsloth (Qwen3.5 4B, Gemma 4 E4B): open it and swap in your own images and labels. To write the training in your own code, use TRL, the standard Hugging Face library, as the code below does. To fine-tune an image model such as DINOv3 or SigLIP 2 instead, put a small output layer (a regression head) on the global embedding, because your outcome belongs to the whole image. A head on the patch embeddings is for tasks that need one answer per region, such as segmentation.     def __init__(self, backbone):
        super().__init__()
        self.backbone = backbone
        self.head = nn.Linear(backbone.config.hidden_size, 1)
    def forward(self, pixel_values):
        z = self.backbone(pixel_values=pixel_values).pooler_output   # CLS token after the final layer norm
        return self.head(z).squeeze(-1)

model = Regressor(backbone).to(backbone.device)
params = [p for p in model.parameters() if p.requires_grad]   # the head and the adapter only
print("trainable parameters:", sum(p.numel() for p in params))
opt = torch.optim.AdamW(params, lr=1e-4)   # about 10 times a full fine-tuning rate (see above)
loss_fn = nn.MSELoss()                     # for a yes/no outcome use nn.BCEWithLogitsLoss()

model.train()

Getting a number out of a VLM

A VLM normally answers in words, so predicting a number such as a click-through rate takes extra setup. No library covers this from start to finish yet. There are four workable patterns.

  • Prompt the model to choose one answer from a fixed set of labels, which can be numbers such as 1 to 7. This needs no training. You get one label for each image, and you can also read the model's probability for each label. It is the labeling approach of Label images with a VLM. Li and Wagle (2026) show that general-purpose models already work well this way with careful prompting (performing as "Jev" style decision models).
  • For a bounded rating, such as a 1 to 7 scale, fine-tune the model to answer with one word for each level ("bad" through "excellent"). The rating is the average of the levels, weighted by the probability the model gives each word, as Q-Align does for image quality.
  • For a count or a log count, add a small output layer that returns a number instead of words (a regression head). In the Hugging Face transformers library, Qwen3_5ForSequenceClassification with num_labels=1 does this and accepts images.
  • As the cheapest check, take the VLM's internal representation of each image as an embedding and fit the embeddings regression.

Explain the predictions

A heatmap shows which parts of an image pushed a prediction up or down. The methods below make such a map after a model is trained, without changing the model. If you fit the embeddings regression on the average of each image's patch embeddings, the outcome heatmap in Embed images already splits each prediction across the image, up to the regression's constant.

A local method explains one prediction: it shows which pixels in this image moved this score. A global method explains the model as a whole, by naming the concepts it relies on across many images, such as faces or text overlays. These methods also work on the embeddings regression: the frozen image model and the regression on top form one network, so you can run them from the pixels to the predicted outcome.

# cross_val_predict keeps no fitted model, so fit one ridge on all images to explain.

class Predictor(nn.Module):   # image in, predicted outcome out: DINOv3, then the ridge
    def __init__(self, backbone, ridge):
        super().__init__()
        self.backbone = backbone
        self.register_buffer("coef", torch.tensor(ridge.coef_, dtype=torch.float32))
        self.intercept = float(ridge.intercept_)
    def forward(self, pixel_values):
        z = self.backbone(pixel_values=pixel_values).pooler_output   # the global embedding
        return z @ self.coef + self.intercept

model = Predictor(backbone, ridge).eval()

Concepts behind a prediction with CRAFT python · xplique 
import glob, sys
import numpy as np, torch
from PIL import Image
from torchvision.models import resnet50, ResNet50_Weights
from xplique.concepts import CraftTorch

weights = ResNet50_Weights.IMAGENET1K_V2
model = resnet50(weights=weights).eval()
preprocess = weights.transforms()            # resize, crop to 224 x 224, normalize

# CRAFT splits the model in two: g maps an image to activations, h maps activations to the score.
# g must end in a layer whose outputs are never negative (here the ReLU at the end of layer4),
# because CRAFT factors the activations with non-negative matrix factorization (NMF).
g = torch.nn.Sequential(*list(model.children())[:-2])   # image -> 2048 x 7 x 7 activations
h = torch.nn.Sequential(model.avgpool, torch.nn.Flatten(), model.fc)   # activations -> 1000 logits

# For your own predictor, h is your fitted ridge as torch.nn.Linear(n_features, 1) with
# class_id=0 below. DINOv3 patch embeddings can be negative, so CraftTorch rejects them.
# Use a ReLU convolutional network as g, or HolisticCraftTorch with factorizer= set to Semi-NMF
# from the Overcomplete library.

folder = sys.argv[1] if len(sys.argv) > 1 else "ads"
paths = sorted(glob.glob(f"{folder}/*.*"))[:30]   # about 30 images that share the predicted class
images = torch.stack([preprocess(Image.open(p).convert("RGB")) for p in paths])

CLASS_ID = 571                               # the output to explain; ImageNet "gas pump" here
craft = CraftTorch(input_to_latent_model=g, latent_to_logit_model=h,
                   number_of_concepts=10, patch_size=64, batch_size=32,
                   device="cuda" if torch.cuda.is_available() else "cpu")
crops, crops_u, w = craft.fit(images, class_id=CLASS_ID)   # 64-pixel crops and their concept scores
importances = craft.estimate_importance()    # Sobol total index: how much each concept moves the score

for c in np.argsort(importances)[::-1][:5]:
    print(f"concept {c}: importance {importances[c]:.3f}")
craft.plot_concepts_importances()            # bar chart of all concepts
craft.plot_concepts_crops(nb_crops=10)       # the crops that score highest on each concept

Inference with predicted variables

Every measurement tool on this page produces predictions, and predictions have errors. When a predicted label, score, or index enters a regression, those errors bias the coefficient and make its standard error too small. The model's accuracy does not tell you how large the bias is. The fix is a small random sample coded by people (a hand-coded sample), and a regression method that uses that sample to correct the estimate.

The workflow is the same whichever tool made the prediction.

  1. Draw a random sample of images, typically a few hundred. Record each image's chance of being drawn. In a simple random sample every image has the same chance. The hand-coded sample from step 4 of the labeling workflow can serve, if it was drawn this way.
  2. Have people code the variable on that sample, using the same definition the model was given.
  3. Run the model on every image, including the coded sample.
  4. Estimate your regression with one of the corrections below. It uses the coded sample to measure and remove the prediction error.

If you trained the model yourself, leave its training images out of the regression, or use cross-fitted predictions.

Fine-tune a generator with LoRA

You can teach an open model a subject or a visual style from your own images. The standard method is LoRA, described in Predict outcomes. The original model stays untouched, and training produces a small adapter file.

  • To teach one product or mascot, use about 5 to 30 photos of it and a made-up name for it, such as "sks bottle". The model learns to draw the product whenever that name appears in a prompt. This recipe is called DreamBooth.
  • To teach a visual style, use a few hundred images, each with a short caption.
  • Some makers release two versions of a model: a fast version that has been simplified for quick generation, and the full "base" version. Train on the base version when there is one.

The diffusers DreamBooth scripts, used in the code below, show every step in Python. ai-toolkit is the quickest to start and has a point-and-click interface. Both support Qwen-Image and FLUX.2.

Design notes for stimuli

  • An image generator starts every picture from random noise, and a number called the seed fixes that noise. To change one attribute and hold everything else fixed, keep the seed the same and change only the prompt or the strength of your LoRA. OpenAI's and Microsoft's image APIs do not let you fix the seed. Some closed APIs do, such as FLUX.2 [pro].
  • Agencies often use ad-creative tools such as AdCreative.ai and Creatify, which run on the same kinds of generators. AdCreative.ai's API does not let you fix the seed or name the model version. Creatify's API lets you name the model and its version, and some of its image models take a seed. Their terms limit what you can do with the outputs: AdCreative.ai keeps ownership and bars benchmarking, and Creatify bars training models on them. Read the terms before you use them for stimuli.
  • Asking a model to edit an image ("make the bottle green") can also change things you did not ask for. Measure how much the rest of the image changed and report it as a manipulation check. ImgEdit-Bench's detail-preservation score, in Track it above, is one such measure.
  • Generate the full stimulus set once and archive the files with their prompts, the model name, and the date (see Stay current). If you may need new stimuli later, use an open model and keep a copy of it.
  • Gemini images carry a hidden SynthID watermark. OpenAI images can carry the same watermark and content credentials (C2PA), a record inside the file that says how the image was made. Open models add no marking. Since 2 August 2026, Article 50(2) of the EU AI Act requires providers of image generators to mark outputs in a machine-readable way. Generators already on the market before that date must comply by 2 December 2026. Article 50(4) requires anyone who uses an AI system to make or alter a deepfake (a realistic AI-made image of a real person, object, or place) to disclose that it is AI-generated.

    raise ValueError(f"The ad is {len(src) / src_fps:.1f} s long. "
                     f"{N} frames at 16 fps need at least {N / 16:.1f} s.")

# Mask: white means regenerate, black means keep. This rectangle covers the top half,
# where the background is. A mask that traces the object fits better.

grey = PIL.Image.new("RGB", (W, H), (128, 128, 128))
frames = [PIL.Image.composite(grey, f, mask) for f in frames]   # grey out the masked area

edited = pipe(
    video=frames, mask=[mask] * N,
    prompt="A plain white studio backdrop",   # describe what fills the masked area
    height=H, width=W, num_frames=N, num_inference_steps=30, guidance_scale=5.0,
    generator=torch.Generator().manual_seed(0),   # fixed seed: same clip, same edit
).frames[0]

More tools

Specialized tools for measuring specific things in an image: where an object is and how much of the frame it covers, what text the ad contains, whether a face looks at the camera, and where viewers are likely to look. They are useful for building interpretable features and controls, but most projects need the earlier sections first.

A VLM or a specialist?

To get several labels as named fields (JSON), see Label images. VLMs do worse than specialist tools when the answer is measured in pixels, such as where an object sits or how much of the image it covers. On ODinW-13, a benchmark that scores how well predicted boxes match hand-drawn boxes (mAP), Qwen3-VL-235B scores 48.6 and SAM 3 scores 61.0. The two papers score slightly differently, so read the gap as approximate. Use a VLM for category labels and a specialist tool for boxes, outlines (masks), and areas. Either way, check the output against a hand-coded sample.

Detect and segment objects

Detection draws a box around each instance of a named thing, such as a logo, a person, or a bottle. Segmentation gives its exact outline. From the outline you can compute area share, the fraction of the frame the object covers. Text-prompted models work with no training. Detectors fine-tuned on a few hundred of your own labeled images are faster and more accurate on unusual images.

from PIL import Image
from transformers import Sam3Model, Sam3Processor

model = Sam3Model.from_pretrained("facebook/sam3", device_map="auto")   # gated: accept the licence

    inputs = processor(images=image, text=concept, return_tensors="pt").to(model.device)
    with torch.no_grad():
        outputs = model(**inputs)
    res = processor.post_process_instance_segmentation(
        outputs, threshold=0.5, mask_threshold=0.5,
        target_sizes=inputs.get("original_sizes").tolist())[0]

    print(f"{concept}: {len(masks)} found, area share {share:.3f}")

import numpy as np
import torch
from PIL import Image
from scipy.ndimage import zoom
from scipy.special import logsumexp
import deepgaze_pytorch

DEVICE = "cpu"   # or "cuda"
model = deepgaze_pytorch.DeepGazeIIE(pretrained=True).to(DEVICE)

# Trained on images about 1024 px on the long side: resize your ads to match
img = Image.open("ad_0193.jpg").convert("RGB")
s = 1024 / max(img.size)
img = img.resize((round(img.width * s), round(img.height * s)))   # long side 1024 px
image = np.array(img)
# centerbias_mit1003.npy is on the repo's v1.0.0 release page: a log density over a 1024 x 1024 image
centerbias_template = np.load("centerbias_mit1003.npy")
centerbias = zoom(centerbias_template, (image.shape[0]/centerbias_template.shape[0], image.shape[1]/centerbias_template.shape[1]), order=0, mode="nearest")
centerbias -= logsumexp(centerbias)

image_tensor = torch.tensor([image.transpose(2, 0, 1)]).to(DEVICE)
centerbias_tensor = torch.tensor([centerbias]).to(DEVICE)
with torch.no_grad():
    log_density_prediction = model(image_tensor, centerbias_tensor)

density = log_density_prediction.exp()[0, 0].cpu().numpy()   # sums to 1 over all pixels
x0, y0, x1, y1 = 415, 640, 580, 860      # logo box in pixels of the resized image
print(f"attention on logo {density[y0:y1, x0:x1].sum():.3f}, logo area share {(x1-x0)*(y1-y0)/density.size:.3f}")
Image.fromarray(np.uint8(255 * density / density.max())).save("saliency_ad_0193.png")
